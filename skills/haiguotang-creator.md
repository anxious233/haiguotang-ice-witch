# 海龟汤谜题创作 · Haiguotang Creator

## 技能目的

基于用户提供的核心概念，创作精炼、推理性强、层次丰富的海龟汤谜题。支持单谜题独立打磨或多谜题串联叙事。全程提供汤底对照，通过编号反馈机制进行迭代修改。

---

## 核心原则

### 海龟汤格式

- **汤面**：谜题正文，描述一个不完整或有疑点的场景，让玩家通过提问还原真相。汤面必须**信息自足**——DM 只回答是/不是，不做引导。每句话都必须是一个可触发提问的钩子。
- **汤底**：完整真相，包含所有隐藏信息和逻辑链条
- **提问机制**：玩家读完汤面后自然产生疑问，DM 仅验证（是/不是/无关）。汤面中不设"引导问题"段落——引导应由汤面自身完成

### 创作哲学

1. **线索隐晦不直白**：信息埋藏于叙事缝隙中，不直接标注"注意这个"
2. **汤面具推算能力**：玩家通过已知信息+合理提问能独立还原，不需要瞎猜或专业知识
3. **难度适中**：汤面看似简单，但关键信息经过精心隐藏，需要2-4轮关键提问才能触及核心
4. **背景自然融入**：世界观和设定通过解谜逐步揭示，禁止前置大段背景铺陈
5. **层层递进**：每个问题引导向更深层的真相，让发现感逐级增强

### 写作风格

| 原则 | 说明 |
|------|------|
| 精炼凝练 | 每个字都要有信息量，砍掉一切冗余描写 |
| 信息密度高 | 汤面 100-300 字，承载 3-5 层隐藏信息。每个句子都是一扇小门，推开才能看到更多 |
| 视角一致 | 汤面使用单一视角叙述。如村民视角：用村民能理解的语言描述一切，不说他们不知道的概念 |
| 拒绝术语 | 删除所有需要专业知识的词汇（冬至→"白天最短那天"、冻土线→"地面上的碎石痕迹"），线索必须通过人物行为驱动而非知识门槛 |
| 编号反馈 | 用户用数字编号列表给出迭代意见，精确对应修订 |

## 工作流程

### Phase 0：根基建立（创作前必须完成）

**不要在概念模糊时开始写汤面。** 先完成以下四个维度的设计：

| 维度 | 要回答的问题 | 产出 |
|------|------------|------|
| **人物** | 每个核心角色的心理内核是什么？他们为什么这样做，不是"为了什么"？ | 角色心理档案（欲望/恐惧/盲区） |
| **故事** | 真实层（汤底）发生了什么？呈现层（汤面）只露出哪一角？ | 双重叙事时间线 |
| **悬念** | 玩家的认知路径是什么？从哪个默认框架出发，经哪些线索破除？ | 认知路径图（框架→裂缝→啊哈） |
| **视角** | 汤面用谁的视角？叙述者知道多少、不知道多少？ | 视角规则（能用/不能用什么词） |

**角色设计原则**：
- 功能性角色必须为己私欲行动，不为"部落"或"真相"
- 主角是被卷入的局外人，不是主动的启蒙者
- 安排一个旁观者角色（记录者/沉默者）——不参与争论，其清醒来自不做任何人的盟友

### Phase 1：认知路径设计

先设计玩家的心理路线，再写汤面：

1. **确定玩家的默认框架**：玩家进入汤面时，看到废土+冰封+旧时代人，会默认什么？（如"核冬天"）
2. **设计破局线索**：每组线索必须同时满足——由人物行为驱动（不需要专业知识）、在汤面中可被感知（不依赖 DM 引导）、能让玩家自己意识到默认框架有裂缝
3. **线索分级**：从易到难排列，第一组线索应为直觉级（如"天空颜色不对"），最后一组为铁证级（如"冰裂准时六十年"）

**线索设计铁律**：不需要专业知识。玩家只需要知道默认框架"应该是什么样"，然后看汤面中的描写和它撞车。

### Phase 2：汤面写作（信息自足）

汤面必须是一组**微谜题的集合**——每个句子都是一道小门，玩家读了自然想问下一个问题。

- 每句话写完后检查：读者读到这里会问什么？如果不会产生疑问，删除或重写
- DM 只答是/不是——汤面不能依赖 DM 的引导补充信息
- 超能力等设定必须贯穿全文（不能只在第二行闪现一次），用角色行为自然呈现
- 不使用角色不可能知道的词汇（末世人不计"冬至"、"代"、"冻土线"）

### Phase 3：首轮创作

1. **先写汤底**：完整真相先行，确保逻辑自洽
2. **再写汤面**：从汤底反向裁剪，每个被隐藏的信息都必须是玩家能通过提问还原的
3. **信息自足检查**：逐句验证——每句话是否都能触发一个具体的问题方向

### Phase 4：迭代打磨

用户给出编号反馈后，按以下流程处理：

1. **精确对应**：每个编号对应一个修改
2. **提供对比**：展示旧→新的变化
3. **附带说明**：每条修改的原因和效果
4. **保留汤底**：每次迭代重新输出完整汤底

### Phase 5：多谜题串联

三部曲标准结构（基于冰之魔女实战）：

| 谜题 | 定位 | 核心功能 |
|------|------|---------|
| P1 | 表层事件 | 建立默认框架→破除。谜底：寒冷是自然现象 |
| P2 | 明暗双线 | 明线：正义联盟推翻暴政。暗线：魔女在利用所有人。读者和主角一起被骗 |
| P3 | 终极反转 | 因果颠倒。魔女不是寒冷的原因，是寒冷的产物。她不是"坏人"，她是冰河期本身

## 迭代经验 · 实战教训

以下来自冰之魔女三谜题的两次完整创作循环（旧版 8 轮 + 重构版）：

### 1. 根基先于文字

**❌ 错误做法**：拿到概念就开始写汤面，边写边想
**✅ 正确做法**：先走完 Phase 0（人物→故事→悬念→视角），再动笔。根基不稳的汤面在迭代中会被反复推翻，浪费时间。

### 2. 认知路径设计

**❌ 错误做法**：用专业知识作为破局线索（地质学、天文学），玩家根本看不懂
**✅ 正确做法**：用人物行为驱动。陈觉自己去找核冬天的证据但找不到——玩家跟着他一起发现"默认框架解释不了"。三组线索：天空颜色、废墟状态、冰裂准时——都不需要专业知识。

### 3. 汤面信息自足（DM 无引导）

**❌ 错误做法**：汤面中写"冻土线退了不止一年"，期待 DM 解释这是什么意思
**✅ 正确做法**：汤面中的每一句都必须是一个玩家读完后自然会问的钩子。DM 只回答是/不是——汤面必须自己把方向给出来。"冻土线"这种词直接删除，改为角色可感知的描述。

### 4. 视角一致：叙述者不知道的东西不能说

**❌ 错误做法**：用村民视角但写"旧楼""冬至""废墟"
**✅ 正确做法**：村民视角下，旧楼是"比树还高的石头骨架"，冬至是"白天最短那天"，废墟是"猎场北边的老地方"。任何角色不可能知道的词汇都是知识污染。

### 5. 明暗双线（P2 专用）

P2 的核心结构：**表面是一个完整的好故事，底下是另一层完整的真相。**

- **明线**：主角联合魔女、盟友推翻暴政，魔女被正名为"冰之圣女"——这个故事本身是自洽的、感人的
- **暗线**：魔女在利用所有人。她提供的"证据"是有选择性的，她收编能力者，她在清除认识她真面目的人
- **关键**：暗线的线索要撒在明线的叙事缝隙中——流民说"突然变冷"（不是冰河期）、少年觉得她"太好了"、某些遗物从未被提供

明线必须本身站得住。读者在 P2 应该真心觉得她是好人，P3 的冲击力来自"我被她骗了"——不只是陈觉被骗了，读者也被骗了。

### 6. "知天者"的嘲弄

主角被赋予一个光环头衔（知天者），但这个头衔本身就是讽刺——他忙着查签筒黑幕，完全没看见面前的人才是更大的问题。头衔是叙事陷阱的一种形式。

### 7. 超能力的贯穿分布

超能力设定不能只在汤面开头闪现一次。必须贯穿全文——探路人在听地热，火焰人在融冰，大力士在搬运，药师在催苗。不说"能力者"三个字，但它一直在。这是世界的基调。

### 8. 功能性角色的私欲驱动

所有功能性角色必须为自己的利益行动：
- 长老：保权力（"祖宗之法不可变"）
- 猎队领头的：找替罪羊（自己懦弱不敢不送女儿→必须有人负责）
- 少年能力者：渴望被看见（被忽略太久的青春期情绪）
- 流民头领：纯粹生存（不修饰，只求自己活）

没有人是"为了部落"或"为了真相"。正是这些私欲的碰撞制造了失控的混乱。

### 9. 旁观者角色

安排一个不参与任何争论的角色（老药师）。她只是看着一切发生——长老保权力、猎队愧疚爆炸、少年求关注、流民生存本能。她谁也阻止不了，只能保护身边几个人。**她的清醒来自不做任何人的盟友。**

她的记录（冰裂之日六十年）不是科学精神——是她的生活方式。不需要解释，只需要呈现。

### 10. 迭代写作习惯

- 先定人物心理内核，再定故事结构，再定悬念设计，最后写汤面
- 每次修改前先读已有文档，建立完整上下文
- 改动要精确对应到用户编号（不做不必要的调整）
- 关注"玩家读完汤面后会问什么"——这是所有修改的唯一检验标准

## 注意事项

1. **永远先写汤底再写汤面**：不能想一出写一出，逻辑必须前置
2. **每次迭代输出完整汤底**：用户需要对照检查，不能只说"第X处改了"
3. **尊重用户编号体系**：用户用什么编号方式（1. 2. 3. 或 a) b) c) 或 ① ② ③），原样对应
4. **不主动建议方向**：用户说"继续"才继续，说"改"才改，不要替用户规划下一条怎么改
5. **背景通过解谜揭示**：汤面中不设"背景说明"段落，所有设定信息必须埋在叙事中
6. **保持克制的语言**："他说"、"她看见"、"那里有"——简洁、冷静、不渲染
